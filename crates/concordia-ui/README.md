# concordia-ui

Concordia's in-game UI: retained widgets as ECS components (`UiRoot`, `UiNode`, `UiStyle`, `UiThemed`, `UiText`, `UiImage`, `UiNinePatch`, `UiProgress`, `UiSeparator`, and the controls `UiButton`, `UiToggle`, `UiSlider`, `UiDropdown`, `UiTabs`, `UiScroll`, `UiTooltip`, `UiFocus`, `UiSounds`, `UiTextBox`, `UiSpinBox`, `UiList`) saved in ordinary scenes and edited through the Engine API like any component. Containers lay out with taffy (CSS flexbox and grid, plus a stack), and nodes can be pinned with Godot-style anchors and offsets. Roots scale from a design canvas to any window. Text is shaped by parley (styled runs, wrapping, alignment, ellipsis) and rasterized by swash into a glyph atlas, from bundled Noto fonts or imported ones. `.theme.ron` themes give classes per-state styles. Text boxes edit typed text (selection, clipboard, password masking), and roots can float in the world over their entity (damage numbers, name plates), taking clicks like screen roots when the project renders. A box grows to fit its text unless the text clips. Controls respond to the pointer, wheel and keyboard inside the simulation, from input actions, so replays reproduce every click; they raise signals gameplay hears, play sound cues, and take clicks before click-to-move sees them. The `[ui]` engine module serves `ui.inspect` (layout as numbers) and `ui.hit_test` (what is under a point), and hands the renderer a draw list for its UI pass. Layout, text and atlases are presentation: they never change a world hash (ADR-0060).

See `AGENTS.md` for invariants, tests and references.
