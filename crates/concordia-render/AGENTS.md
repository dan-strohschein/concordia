# concordia-render: agent guide

## Purpose
The renderer (ADR-0040): render graph, forward shading of Substrate-style materials (ADR-0068), GPU skinning of posed characters (M2 2.4.2, ADR-0074), cameras, headless capture, and `capture.screenshot` (via `RenderModule`).

## Public entry points
- `graph::RenderGraph`: `create_texture` (transient), `import_texture`, and `add_pass` / `add_pass_recorded` with `PassBuilder::uses(texture, Use)` and `side_effect()`. `compile(footprint)` returns a `CompiledGraph` with `pass_names`, `barriers_before`, `memory_plan`, `to_dot` and `execute`.
- Components: `Camera` (`Projection` perspective/orthographic, reverse-Z; `Msaa`; `exposure_ev100`; `Tonemap`; `priority`), `DirectionalLight`, and `PointLight` / `SpotLight` (lumens, range, cone half-angles). Since M4 4.1b1 they, `CascadeSettings`, `view_matrix`, `candela`, `Projection::matrix` and the CPU tonemap are defined in `concordia-render-types` (shared with the path tracer) and re-exported here under the same paths.
- `tonemap::apply` gives CPU references for AgX (default), Khronos PBR Neutral, ACES fitted and Linear; the shader must match them (tested).
- `cluster::{ClusterGrid, ClusterSettings, ClusterCuller}`: the froxel grid (16×9×24; exponential slices for perspective, linear for ortho), the CPU reference `assign`, and the GPU culler (`cull` reads back). `Renderer::stats()` reports light counts and cluster overflow.
- `Environment` (HDR equirect `map`, `intensity`, `skybox`) and `ibl::{Equirect, sh9_irradiance, eval_sh9, prefilter, integrate_brdf, brdf_lut}`: image-based lighting computed on the CPU (deterministic, tested). The BRDF table and sampling come from `concordia-material` (re-exported, 2.3a). The renderer caches six prefiltered levels and SH9 per map, plus one BRDF table per renderer, built on first use. An `Environment` has no position: entities with one are extracted even without a `Transform` (`extract::placement` / `placements`, shared by full extraction and the scene cache).
- `shadow::{CascadeSettings, fit_cascades, split_distances}`: `DirectionalLight.shadows` enables cascaded shadows. Cascades are fitted on the CPU (practical splits, bounding spheres snapped to the texel grid, light depth covering all casters).
- `RenderWorld::extract(&World)` copies draws, lights, cameras and poses with world transforms, in entity-id order (`assemble` / `assemble_owned` join per-entity items). `camera(Option<EntityId>)` picks the requested camera, or else the highest priority.
- Representation LOD (2.4b.2, ADR-0076): `Representation { instanced: Option<MeshRenderer>, instanced_from, hidden_from }` (`validate`; presentation-only through `#[reflect(presentation)]`), `RenderWorld::represented(eye)` (the world as a camera at `eye` draws it, with palettes for the draws still skinned), `DrawItem::{representation, instanced, sim_lod}`, `RenderWorld::poses` (extracted) beside `skins` (as drawn). `ViewMode::lod`.
- Skinning (2.4.2): `DrawItem::skin` (the entity whose pose deforms the draw), `EntityItems::pose` (`PoseView`: entity, world, `Arc<Skeleton>`, `Pose`) and `RenderWorld::skins` (`SkinView`: entity, world, joint palette), built by `RenderWorld::assemble`. `shaders/skin.slang` (`skin_vertex`) is imported by `forward.slang`.
- `Renderer::new(Arc<dyn Device>, Box<dyn ShaderCompiler>)` and `render(&RenderWorld, &mut dyn AssetSource, &RenderRequest) -> Image` (sRGB RGBA8). `forget(&AssetRef)` drops the GPU copy of a mesh, texture or environment map, so the next frame uploads it again; `material_variants()` counts the shape-specialized forward shaders compiled so far.
- `AssetSource` (meshes, layered `Material`s, textures) is implemented for `AssetDb` and `MemoryAssets` (tests, procedural content, built-ins).
- Closure budget (ADR-0068): `platform_closure_budget(&RhiCaps)` (8 on Metal), `effective_closure_budget(platform, project)`, `Renderer::set_closure_budget` / `closure_budget` / `closure_reports` (the last frame's downgraded materials). `ClosureBudget` and `ClosureReport` are re-exported from `concordia-material`.
- `RenderModule::new(DeviceFactory)` (`.with_closure_budget(..)` for a project's `[render] closure_budget`) provides `capture.screenshot` (result `image: EncodedImage`, which MCP returns as image content; `skeleton: true` adds the skeleton overlay to that capture whatever the editor's overlays are, M2 2.4.5) and `render.stats` (the last frame's `FrameStats`, recorded by the render thread, with `closure_budget` and `downgraded_materials`: `MaterialDowngrade` / `ClosureMergeStats` / `MergedOperator`).
- Perf mode (M4 4.1a, ADR-0089): `perf::{PassTimer, PassTime, PassTiming, pass_times}`; `CompiledGraph::execute_timed(.., &mut PassTimer)`; `Renderer::set_perf_mode` / `perf_mode` / `device`; `RenderStats::{pass_timing, timed_passes}`; `RenderModule::with_perf_mode` (`[render] perf_mode` in a project). `render.stats` gains `pass_timing` (`off`, `unsupported`, `measured`) and `passes: [{name, start_ms, gpu_ms}]`.
- `ibl::albedo_table()`: the split-sum, direct-lobe and sheen albedo tables as one 64×32 RGBA16F texture.
- `ViewMode` (`RenderRequest::view_mode`, `capture.screenshot` / `viewport.overlays` `view_mode`): lit, unlit, wireframe, normals, albedo, roughness_metallic, overdraw, shadow_cascades, light_clusters, closures, haze, fuzz, subsurface, thin_film, lod.
- Overlays (2.4.4): `Overlays::skeleton` draws every posed skeleton (`SkinView::joints`, each joint in its entity's space, and `SkinView::skeleton`): a line from each joint to its parent and a dot per joint, on top of the image. Selection boxes use each draw's placement (posed bounds for skinned draws).
- Debug layers (2.5a, ADR-0077): `RenderRequest::debug` carries world-space `DebugGeometry`; `capture.screenshot`'s `debug` (layer names; an unknown one is `InvalidParams` listing the layers) and `Overlays::debug` (with `overlays: true`, and in the viewport) resolve names through `Engine::debug_geometry`. They are drawn under the selection and gizmos: filled triangles, then 1.5-point lines, premultiplied, skipping anything behind the eye.
- Gizmos: `GizmoMode` (move, rotate, scale) on `GizmoOverlay`; `gizmo_handles` / `gizmo_rings`, `gizmo_hit` / `ring_hit`, `gizmo_pick(mode, ..)`; drag math `axis_delta`, `rotate_angle`, `scale_factor`.
- The meshlet path (M4 4.3a, ADR-0100): `Renderer::set_meshlets` / `meshlets` (on by default), `RenderModule::with_meshlets` (`[render] meshlets`); `MeshletPush`, `CullPush` and `CompactPush` mirror `shaders/meshlet.slang`, `ScanPush` and `ScanAddPush` `shaders/scan.slang`; `TaskPush` (M4 4.3b) mirrors the mesh stages' push block; `RenderStats` / `FrameStats` `raster_path` (`RasterPath::{forward, compute_indirect, mesh_shader}`) and `meshlets` (`MeshletCounts`, with `indirect_draws` or `mesh_draws`); `ViewMode::{meshlets, triangles}`. Motion vectors (M4 4.3b2): `Renderer::set_motion_readback` / `read_motion` (`MotionImage`, UV units, y down), `Renderer::reset_motion_history`, `ViewMode::motion`. Inside: `meshlet.rs` (the path rule, `route` (compute or mesh shaders), `task_groups`, `MeshletInfo`, mesh-table rows, `plan` into buckets and work items) and `meshlet_pass.rs` (the frame's buffers, the `meshlet.cull` pass on the compute route, `BucketDraw`s for either route). GPU culling (M4 4.4a): `Culling` (`Renderer::set_culling`, `RenderModule::with_culling`, `[render] culling`), `CullView` and `CullCode` (the CPU reference of the GPU's tests, `cull.rs`), `Renderer::set_cull_readback` / `read_culling` (`CulledMeshlet` per candidate, `cull_stats.rs`), `MeshletCounts`' per-stage counts; `scan.rs` (deterministic GPU exclusive prefix sums, reusable). Two-pass occlusion (M4 4.4b): `Culling::occlusion`, `CullCode::{Occluded, DrawnLate}`, `MeshletCounts::{after_occlusion, drawn_early, drawn_late}`, `ViewMode::{occlusion, hzb}`, `HzbPush`; inside, `hzb.rs` (the HZB layout and build), `visibility.rs` (per-meshlet visibility runs and their GPU buffer) and `forward_pass.rs` (the forward pass, split around the HZB).

## Invariants
- Frame: light clustering (compute) → one depth pass per shadow cascade (persistent maps imported into the graph) → forward pass (HDR `Rgba16Float`, depth `Depth32Float` cleared to 0 with `GreaterEqual`, optional 4× MSAA resolved into HDR) → tonemap (Khronos PBR Neutral or clamp) → sRGB output → readback. All of it is scheduled by the render graph, with transients placed in one heap per frame.
- Shader data read through pointers uses only `float4`/`uint4` rows (identical layout on every backend). Push constants are mirrored with `shader_struct!` and checked by `check_layout`.
- Hot reload (2.3c): `RenderState` remembers the kind and `AssetDb::generation` of each imported mesh, material and texture (environment maps included) when it is sent to the render thread. A later frame or capture re-sends any whose generation moved (`material.set`, `asset.import` or a watched file); a material brings textures it now needs. The render thread calls `Renderer::forget` on every asset it receives (a no-op the first time). Forgotten GPU buffers and textures wait in `Renderer::retired` until the next frame adopts them, and are freed when that frame retires, after every earlier frame that may still read them.
- Materials (ADR-0068): at upload each material is fitted to the closure budget (`fit_budget`) and compiled (`MaterialProgram`), with its `ProgramShape` (`shape.rs`), and kept until its content or the budget changes (`programs.rs`); a downgrade is logged once (`material simplified to fit the closure budget`, fields `material`, `closures`, `budget`, `merged`, `dropped`) and reported in every frame's `render.stats` that draws it. The material buffer holds, per material, a header row, one row per op and eight rows per closure (`material_rows.rs`, mirrored in `forward.slang`); `DrawPush.material` is the first row. At most 8 closures and 64 ops.
- Shape variants (2.3c follow-ups): a program with more than one op draws with `forward.slang`'s `fs` compiled for its shape. The shape's defines are `SHAPE_OPS`, `SHAPE_KINDS`, `SHAPE_SLABS`, `SHAPE_CLOSURES`, `SHAPE_FEATURES` and `SHAPE_LAYERED`, from `ProgramShape::defines`. `Pipelines` keeps the compiler and one fragment source per shape, and forward pipelines are keyed by (samples, double-sided, blend, shape). The base shader (no defines) is the one-slab shape, with features read from the rows. It also serves the wireframe and overdraw pipelines, which never run the program (they find closure 0 through the header's op count). Values stay in the rows, so a value edit never recompiles; a new shape costs one compile (about 0.2 s plus Metal's, cached in the DDC).
- `forward.slang` first runs the mask test from the program's alpha alone (`program_alpha`, still a dynamic loop over the rows), then loads the shape's closures (textures applied, and their view-only terms: N·V, the diffuse share 1 − E_spec(N·V), the sheen albedo, and the view-side transmittance when layered) into the thread-private `g_closures`. It then runs the shape's unrolled program: once per light (sun, then each clustered punctual light), once for image-based lighting (each closure lit by the environment, transmittance toward the mirror direction = toward the view), and once for the albedo (unlit, albedo view). A lit one-slab program skips `g_closures` and the program entirely (registers only), and a slab with no optional features uses `eval_plain`. Light-side transmittance is computed only when `SHAPE_LAYERED` says there is a vertical layer.
- **Metal miscompile (Apple's compiler, macOS 26.2, M3 Pro):** discarding on an alpha read back from the thread-private closure array (`g_closures`, or an `inout` array) dropped every masked fragment though the compared values were right; passing the array by value works but is ~40× slower. Reduced in 2.3c to `tools/repros/metal-discard-after-private-array` (hand-written MSL and a Swift host, no Slang): Slang's MSL is correct, so it is Metal's compiler; to report upstream. Keep the mask test before the closure loads, from the program's alpha alone; `masked_materials_keep_fragments_at_or_above_the_cutoff` guards it. It mirrors `concordia-material` exactly; `shader_matches_cpu_reference_per_feature` checks every feature and operator against `MaterialProgram::eval` (≤ 1.2 sRGB steps), and mutations of each term are caught by it.
- Energy (ADR-0068): diffuse, direct and ambient, is scaled by 1 − E_spec(N·V) from the direct-lobe table, not M1's 1 − F(V·H). The albedo tables are uploaded on the first frame, with or without an environment.
- Unlit and emissive output are display-referred; exposure scales only light.
- IBL per closure: diffuse from SH9 irradiance (× 1 − E_spec); specular = lerp of two prefiltered equirect levels (roughness × 5) × (F0·A + B) from the split-sum table, per lobe (haze blended by weight; thin film replaces F0 at N·V); sheen = fuzz × E_sheen × the prefiltered level at the sheen roughness, over the rest dimmed by 1 − max(fuzz)·E_sheen; all scaled by intensity × exposure and by occlusion. The sky is drawn first in the forward pass (no depth test or write); its rays come from unprojecting each pixel at two depths, which works for ortho too. Equirect u = 0.5 at -Z, increasing toward +X; v = 0 straight up.
- Shadows: reverse-Z depth; filtered PCF (a box of bilinear compares, kernel radius 1 or 2); bias = constant + normal offset (texels) + slope-scaled ((radius + 1) texels × tan θ, capped at 10), so the whole PCF footprint clears the receiver. Stabilized cascades move in whole texels (the shimmer test pans one pixel per frame: 0 changed pixels when stabilized vs ~900 without).
- Punctual lights: intensity = lumens / 4π cd (spots are not concentrated by their cone); inverse-square falloff windowed to zero at `range`. Clusters hold at most `max_per_cluster` lights, in ascending index order; dropped assignments are counted (`RenderStats::cluster_overflow`) and logged, never silent.
- Transparency: `AlphaMode::Blend` draws after the opaque ones, back to front by the view depth of their bounds' center, with premultiplied alpha and no depth write; `Mask` discards below the cutoff.
- Rendering is deterministic on one device (same scene → same bytes); draws are ordered by pipeline, then entity id.
- Skinning (2.4.2, ADR-0074):
  - **Which pose:** a draw with `Skinned` takes its own `Pose`, or the nearest ancestor's whose `Skinned` names the same skin (an import's extra parts are children). The skeleton comes from the play world's `Arc<AnimLibrary>` resource (`AnimModule`). With no pose or skeleton (the edit world), or a pose of the wrong size, the draw is its bind mesh, unskinned.
  - **Palettes** are built on the CPU in `RenderWorld::assemble`, after interpolation: `Skeleton::palette` (`concordia-anim`), one per posed entity per frame, uploaded as one buffer of `float4` columns whose index is `Frame.buffers.w`. A skinned draw is placed at its posed entity's world matrix; a part's own offset is ignored (glTF §3.7.3: the skinned mesh node's transform is ignored).
  - **Shaders:** `Instance` has a `uint4 skin` row (first palette matrix, joint count; 0 is unskinned). `vs` (forward, wireframe, overdraw) and `shadow_vs` call `skin_vertex` before the instance transform. It mirrors `concordia_anim::skin_vertices` (cofactor for normals; zero-length directions keep the input), and `DrawPush` / `ShadowPush` carry the `joints` (`uint4`) and `weights` (`float4`) streams. Skinned copies of one mesh still draw as one instanced call, each with its own palette.
  - **Validation:** a draw is skinned only if its mesh has joint and weight streams of its vertex count and every joint index is inside the palette, including joints with weight 0, which the shader still reads. Otherwise it falls back to the bind mesh, logged once per mesh.
  - **Bounds:** culling, cascade fitting and blend sorting use `concordia_anim::skinned_bounds` over the per-joint boxes kept at upload (`GpuAssets::joint_bounds`). The shadow cache key includes the palette, so a new pose redraws the shadow maps.
  - **Overlay (2.4.4):** `SkinView` carries the joints in the entity's space (`Skeleton::entity_space`, one model-space pass shared with the palette via `skin_matrices`); bones are drawn at `world · joint`, the same space as attachments and `anim.inspect`'s `world`. The edit world has no poses, so no skeletons.
  - **Interpolation:** `RenderScene::world_at` blends a pose bone by bone (`Pose::lerp`) and its world matrix, like transforms. Rendering never writes the world, so the world hash never depends on it.
- Representation LOD (2.4b.2, ADR-0076, E2):
  - **Chosen per frame by the drawing camera**, never in extraction or the scene cache (they stay camera-agnostic) and never stored: `Renderer` calls `represented(eye)` at the start of each frame, and `pick` does the same from its view's eye. Distance is from the eye to the world position of the entity owning the `Representation`. Boundaries go to the far side: d ≥ `hidden_from` is hidden, d ≥ `instanced_from` (with `instanced` set) is instanced, else full. An invalid one is drawn full, logged once per entity.
  - **Ownership:** a draw's `Representation` is its own, else its nearest ancestor's with the same skin (a character's parts follow the bind mesh). Instanced: the owner draws the cheap mesh with its material and `cast_shadows`, unskinned; other parts aren't drawn. Hidden: nothing is drawn, so no shadow, pick or selection box.
  - **Palettes are built in `represented`**, only for poses that still deform a draw; `assemble` keeps the extracted `poses`. Draws whose pose doesn't fit their skeleton use the bind mesh.
  - Never hashed: `Representation` is presentation-only by type, so every world leaves it out of the hash and simulation may not touch it.
- View modes are one branch in `forward.slang`'s `fs` on `Frame.debug.x` (the `ViewMode` order). `lod` (14) is flat-shaded from the instance row's `skin.z` (simulation level + 1, 0 for none; +16 when instanced): white, then green, yellow, orange, red for levels 0–3; instanced at half display brightness. Debug data views (unlit, wireframe, normals, albedo, roughness/metallic, overdraw, closures and the four feature views) skip the tonemap curve (`Linear`, clamped) and, except unlit, the sky. Albedo and unlit show the program's combined albedo (`MaterialProgram::unlit`); normals and roughness/metallic show the first closure; `closures` colors the closure count (blue 1, green 4, red 8); haze (weight), fuzz (color), subsurface (wrap per channel) and thin film (thickness / 1000 nm) combine each closure's value through the operators, black where absent. Wireframe draws barycentric edges from the corner index (vertices are pulled per triangle corner), so no fill-mode support is needed; it and overdraw use `Pipelines::debug` (no culling, no depth test; overdraw blends additively).
- Perf mode: with it on and a device whose caps `times_passes()`, the frame records `lights.cluster` (the clustering before the graph) and then every graph pass, each in its own RHI timer scope placed after the pass's barriers, so each pass is its own encoder(s). Scope `i` is `RenderStats::timed_passes[i]`; the render thread keeps the names with the frame and fills `passes` when the GPU timing arrives (before or after the record, as `gpu_ms`). Off (the default), no scopes are recorded and frames are unchanged. The overhead is held under 2% of the frame's GPU time (`pass_timer_overhead_under_2_percent`, median of adjacent on/off ratios).
- `render.stats` GPU time comes from the device's completion handler (`Device::submit_timed` for captures, the present callback for viewport frames); it may arrive before the frame is recorded, and `stats::Last` keeps it until then.
- Gizmo rings are unit circles projected and scaled about the entity's screen position to the arrow length (60 px), so an edge-on ring is a line. Rotate angles are measured around the entity on screen (counter-clockwise is positive when the axis faces the eye); scale grows by one per arrow length dragged outward, never below 0.01.
- The device and shaders are created on the first capture, so engines start without a GPU. A missing device is `GpuUnavailable`.
- **Backends (M4 4.1v(b), ADR-0088):** the renderer is backend-neutral: it takes any `Device` and compiles MSL or SPIR-V from `caps().backend`. Devices come from `concordia-rhi-select` (`CONCORDIA_BACKEND`, then the project's `[render] backend`, then `auto`: Metal on macOS, Vulkan elsewhere). Render tests open theirs the same way and compare goldens with the backend's tolerance (`tests/golden/render/tolerances.ron`'s `backends`); a Vulkan failure is written under `target/golden-failures/render/vulkan/`, and Vulkan never blesses. `tests/spirv.rs` compiles every entry point to SPIR-V and runs `check_spirv_module` on any OS. `attach_surface` (unsafe: the caller keeps the native window alive) and `detach_surface`, which must run before the window goes (`concordia run` on `WindowEvent::Closing`; the Linux editor on GTK's `unrealize`). Shaders may read an empty bindless slot; it reads as zero on both backends (Metal's nil entries, Vulkan's null descriptors).
- Meshlet path (4.3a): a draw takes it only when the path is on and its mesh has a valid `MeshletBlob` v1 and is neither skinned nor blended; everything else stays on the M1 path in the same forward pass and depth buffer (buckets draw after the M1 opaque draws, before the blended ones). The blob is uploaded unchanged; an invalid one is logged and the mesh drawn on the M1 path. Buckets follow M1's batches (pipeline, material) plus one shadow-caster bucket per cascade (none when the shadow maps are reused); every candidate entry has a fixed slot. `meshlet_vs` writes the same `VsOut` as `vs` (through `surface_vertex`), and `MeshletPush` keeps `frame`, `materials` and `material` where `DrawPush` has them, so `fs` is shared unchanged. Triangle slots past a meshlet's count collapse to a point outside the clip volume (and read vertex 0).
- Motion vectors (4.3b2): `motion.rs` keeps last frame's world matrix per drawn entity, palette per pose owner and the camera's view-projection; anything not drawn last frame (and everything after `reset_motion_history`, or a full scene update on the render thread) has no motion. The instance row is 224 bytes (`frame::InstanceRow`: model, normal, skin, `prev_model`, `motion` = previous palette start) and `Frame` ends with `prev_view_proj`. `surface_vertex` writes `clip` and `prev_clip` by the same expression, so a still surface is exactly zero; `fs`, `sky_fs` (rotation only) and `grid_fs` return `ForwardOut` (color, motion). The forward pass's second target is `Rg16Float` (MSAA, resolved); blended, debug and grid pipelines mask it (`color_only`). Skinned vertices are skinned twice (this frame's palette, and last frame's, which follows the current ones in the palette buffer when its length matches). One history per renderer: 4.6 makes it per view.
- Mesh-shader route (4.3b): taken per frame when the device has object and mesh shaders with at least 128 output vertices and primitives, except in the `wireframe` and `triangles` views (they need per-triangle data that shared vertices can't carry; per-primitive outputs are out because Slang can't decorate the fragment input for Vulkan). It reuses the work items, buckets and mesh table: `meshlet_object` (32 threads) finds each entry's work item with the same `find_item` as `meshlet_cull`, culls it and launches one mesh group per survivor; `meshlet_mesh` emits the meshlet's ≤ 128 shared vertices (through `meshlet_surface` → `surface_vertex`, whole structs) and triangles; `fs` is shared unchanged (`TaskPush` keeps `frame`, `materials`, `material` at `DrawPush`'s offsets); `meshlet_shadow_mesh` draws the caster bucket into each cascade. One `DrawMeshTasks` per bucket, `task_groups` rows of ≤ 65,535 groups. There is no `meshlet.cull` pass on this route.

- GPU culling (4.4a): meshlet-path instances are culled on the GPU only (the CPU frustum test stays for M1 draws). `meshlet.slang`'s `cull` is the one test both routes call: the instance's box (eight corners, as `cull::Frustum::sees`), the meshlet's sphere, then the normal cone in the instance's local space (meshoptimizer's sphere form, `NormalCone::rejects`), skipped for double-sided buckets, mirrored or non-uniformly scaled instances (beyond 0.1 %), orthographic views and `cutoff` 127. The view table is the camera, then each cascade (frustum only, without the near plane). Every candidate writes a code word (code in bits 0–7, the meshlet's triangles in 8–15); survivors keep slot order on both routes (the compute route compacts with `scan`, the object stage ranks within its group), so culling on and off draw the same triangles in the same order, and nothing uses atomics. `cull.rs`'s `CullView` mirrors the shader and is the tests' reference; keep them in step. The stats come from reading the codes back (a viewport frame's when it retires). The culling switches are part of the shadow cache key.
- Two-pass occlusion (4.4b): the frame splits (`forward`, `meshlet.hzb`, `meshlet.cull_late` on the compute route, `forward_late`) only when the test is on, something takes the meshlet path, the depth is single-sample or the device has `depth_resolve_min`, and the projection is symmetric (`SphereProjection::new`); otherwise it is one pass as before. `meshlet.slang`'s `decide` is the only place passes differ, and both routes call it, so they write identical codes. The HZB is reverse-Z: each texel the min (farthest) of its parents; a sphere is occluded only when its nearest depth is smaller than the min of the up to 2 × 2 texels its projected rectangle (one pixel wider each side) covers, and never when it reaches the near plane. Pass 1 has no HZB test, so missing or stale visibility (the first frame, a camera cut, a new entity, a grown buffer) only costs time. Visibility is a word per meshlet because nothing uses atomics. In the render graph a read added between two writes runs between them; keep `meshlet.hzb` added after `forward` and before `forward_late`.

## How to test
`cargo nextest run --workspace -E 'package(concordia-render)'`. The graph, camera and extraction tests are CPU-only. `tests/skinning.rs` covers skinning; `gpu_skinning_matches_cpu_skinning` reads vertices back through the test-only kernel `tests/shaders/skin_readback.slang`, which imports `skin.slang` (no production API), and the image tests compare skinned draws with CPU-skinned meshes drawn unskinned. Render and capture tests skip without a GPU unless `CONCORDIA_REQUIRE_GPU=1`. glTF conformance goldens (`tests/gltf.rs`) need `just gltf-assets`. Goldens live in `tests/golden/render/`: inspect a new image by eye, then run `CONCORDIA_BLESS=1` (never in CI). On Vulkan: `CONCORDIA_BACKEND=vulkan` (lavapipe in the on-demand `vulkan` workflow, with `CONCORDIA_REQUIRE_VULKAN=1` and `CONCORDIA_VULKAN_VALIDATION=strict`); `CONCORDIA_GOLDEN_KEEP=1` keeps every comparison and its score, passing or not, for a review page.

## Performance
- `cargo bench -p concordia-render --bench many_lights` (M3 Pro, 2026-11-18): 1,024 point lights at 1920×1080 ortho, median **6.5 ms per frame wall clock**. Re-measured 2026-11-20 on the same Mac: main (M1 shading) 2.5–3.2 ms median, best 2.46 ms; 2.3b's closure interpreter 2.9–3.2 ms median, best 2.90 ms (one-slab materials, about 15–18% slower). A first version that re-ran view-only terms and copied the closure array per light took 130 ms. Lit one-slab materials keep their closure in registers and featureless slabs take `eval_plain`; four feature branches per light cost about 0.7 ms. That includes CPU work, a synchronous submit and an 8 MB readback. GPU-only time needs timestamp queries, which the RHI doesn't have yet; the plan's target is < 4 ms GPU.
- Layered floors (same bench, same Mac). In 2.3c (2026-11-20) a clear coat (2 closures) took 23.4–23.5 ms and a coat over a fuzzy mix (3 closures) 52.5–54.5 ms, about 8× and 18× one slab. The dynamic interpreter's stack and closure indexing went to thread memory, and per-light transmittance was about half the cost. With shape variants (2026-11-21, three runs, against main's 3.38 / 23.47 / 52.46 ms the same day): one slab **2.95–3.01 ms** (unchanged), a clear coat **4.77–4.85 ms** (1.6×), three closures **7.28–7.44 ms** (2.5×).

- Skinned crowd (2.4.2, `cargo bench -p concordia-render --bench skinned_crowd`, M3 Pro, 2026-11-21, load average 12–18). 1,000 characters, each a 1,024-vertex column skinned to a 65-bone chain, with a shadow-casting sun at 1080p, all in one instanced draw: **6.5–6.6 ms** median per frame, against **2.8–2.9 ms** for the same crowd drawn unskinned. Extraction with 65,000 palette matrices takes 3.1 ms, against 1.3 ms without. The rest of the difference is the 4.2 MB palette upload, the bounds, and skinning in the forward pass and each cascade. Possible follow-ups when crowds need them: 3×4 palette rows, building palettes in parallel or on the GPU, and a compute pre-skin with M4's visibility buffer. `many_lights` is unchanged (three runs each against main the same day: one slab 2.93–3.11 ms vs 2.92–3.38 ms, two closures 4.77–4.87 vs 4.76–4.77 ms, three closures 7.24–7.34 vs 7.18–7.30 ms).

## Common tasks
- **Time the passes:** `Renderer::set_perf_mode(true)` (or `[render] perf_mode = true`), render, then read `render.stats` `passes`; `concordia perf run` measures a whole camera path (ADR-0089).
- **Inspect a frame:** `compiled.to_dot(&graph)` gives Graphviz text; `memory_plan()` lists transient placements.
- **Add a pass:** declare its uses in `add_pass_recorded`. Record commands only, since the graph derives barriers. Look up bindless indices inside the record function (it may return an `RhiError`).
- **Change shader data:** edit `shaders/*.slang` and `frame.rs` (or `material_rows.rs`) together, keeping whole `float4`/`uint4` rows; push structs must pass the layout test.
- **Change skinning:** change `concordia_anim::skin_vertices` and `shaders/skin.slang` together. `gpu_skinning_matches_cpu_skinning` (1e-4) and `skinned_draws_match_cpu_skinned_meshes` must pass.
- **Change a BSDF term:** change `concordia-material` first (with its reference values), then the same lines in its `shaders/material.slang` (since 4.1b1 the slab BSDF and the program combinators live there, and `forward.slang` imports them through `include_dirs()`); `shader_matches_cpu_reference_per_feature` must stay within 1.2 steps, and add a case if the term is not yet exercised (mutate it to check).

## Don'ts
- Don't record barriers by hand inside passes.
- Don't make compilation or draw order depend on hash-map iteration.
- Don't sample with anything but the static samplers (`g_textures.samplers[SAMPLER_*]`).
- Don't change a shading formula in `forward.slang` alone: it must stay the mirror of `concordia-material`.

- Representation crowd (2.4b.2, `cargo bench -p concordia-render --bench crowd_100k`, M3 Pro, 2026-11-21, load average 5–7): cheap cubes on a 1 m grid with a shadow-casting sun at 1080p, one draw call. At 100,000: extraction **47 ms** (134 before: `world_transforms` without per-entity allocations for roots, and `World::get` with one lookup of each kind), the scene cache's update after every entity moved 113 ms (178), interpolation 27 ms (26), the frame **37 ms** (26; `represented` copies the draws once per frame). At 1,000: 0.4, 0.8, 0.2 and 1.9 ms. A columnar, incremental extraction for crowds that move every tick is M7's. Instanced characters build no palette, so 2.4.2's palette follow-ups aren't needed for far crowds.

## Engineering rules
These apply to every change, by humans and agents alike.
1. **TDD on every phase.** Write the tests first, see them fail, implement, then refactor.
2. **SOLID.** Depend on abstractions at crate boundaries; extend through traits rather than by editing callers.
3. **No duplicate functionality.** Before writing any implementation, search for existing functionality (grep, `cargo doc`, crate `AGENTS.md` files). Extend or refactor what exists; never write a parallel version.
4. **Single responsibility at every level:** function, type, module and crate.
5. **Small functions** that do one thing.
6. **Validate parameters.** Every function checks its inputs:
   - Rust: encode invariants in types (newtypes, enums, `NonZero*`); validate at boundaries and return `Result` with a descriptive error; use `debug_assert!` for internal invariants. Public APIs never panic on bad input.
   - TypeScript: strict types, plus runtime validation at API and IPC boundaries.
7. **Short comments.** One-line doc comments on public items; no essays, and no comments that restate the code.
8. **Idiomatic code.**
   - Rust: follow the Rust API Guidelines and keep it clippy-clean; `thiserror` in libraries, `anyhow` only in binaries and tests.
   - Editor UI: idiomatic React and TypeScript, with function components, hooks, strict mode, ESLint and Prettier.
