# ADR-0041: Jolt integration
- Status: Accepted
- Date: 2026-11-18

## Context
M1 needs deterministic rigid bodies, a character controller and scene queries. Jolt Physics (MIT) is best in class. It is C++, so Rust reaches it through a C API. The M1 plan chose to vendor Amer Koleci's joltc and add a small shim, with "grow our own shim" as the fallback.

Integrating it showed that joltc keeps the underlying `JPH::PhysicsSystem` private, and we need it for three things:
- state save and restore (`StateRecorder`), for M3 replay;
- deterministic contact and sensor events: joltc forwards each contact through global callbacks on Jolt's worker threads;
- per-world layer and job-system setup.

Reaching into joltc's private struct layout would be fragile. The published Rust crates (`rolt`/`joltc-sys` on Jolt 5.0, and the young `oxijolt-sys`) would also impose someone else's safe API.

## Decision
- Vendor Jolt **v5.7.0** under `third_party/JoltPhysics`, unmodified, with LICENSE and VENDOR.md. joltc is **not** used.
- `jolt-sys` builds Jolt and a small C++ shim (`shim/concordia_jolt_ext.{h,cpp}`) with CMake, through the `cmake` crate, always in Release. Flags: `CROSS_PLATFORM_DETERMINISTIC=ON`, single precision, no GPU compute, no ObjectStream, debug renderer or profiler.
- The shim's C API is shaped for Concordia: worlds with 16 user layers and a collide matrix, bodies from plain descriptors, stepping, contact begin/end events batched under a lock (no callbacks into Rust), raycasts with layer masks, state save/restore, virtual characters, and counted allocations for leak tests. Every entry point validates its input.
- Bindings are generated by `tools/jolt-bindgen` (its own workspace, so libclang is never a build or CI dependency), committed, and drift-checked by a test that hashes the shim header.
- The safe API is ours, in `concordia-physics`.

## Consequences
Building needs CMake and a C++17 compiler; GitHub's macOS and Ubuntu images include both. A cold build of Jolt and the shim takes about 10 s on the reference Mac. New physics features mean shim code (C++) plus a binding regeneration. Upgrading Jolt means replacing the vendored directory and rerunning the determinism tests on both platforms.

## Alternatives considered
- joltc (tried first): broad coverage, but it hides the physics system needed for state recording and deterministic event batching.
- `rolt`/`joltc-sys` crates: lag Jolt by two minor versions.
- `oxijolt-sys`: young, and its license metadata disagrees between crates.io and GitHub.
- Rapier: pure Rust, but it lacks Jolt's maturity in character control and large-scene performance.

## Update (M2 phase 2.10a, 2026-11-23): characters have an inner body for sensors
- **Problem:** a `CharacterVirtual` is not a body, so sensors never reported characters. A lamp's light or a wagon's refill zone couldn't see the player.
- **Decision:** each character gets Jolt's kinematic inner body, with the same capsule, on the character's moving layer, carrying a user id that maps to the character's entity. Sensors then raise `ContactBegan` and `ContactEnded` naming the character.
- **Limits:** the inner body is for sensors only. The shim's contact listener rejects every other pair with it in `OnContactValidate`, and raycasts and every character's movement skip inner bodies with a body filter. So dynamic bodies, floors and rays behave as before, characters still pass through each other (the crowd keeps them apart, as before), and none collides with its own inner body.
- **Shim changes:** `CjCharacterDesc` gained `user`, and the bindings were regenerated.
