# ADR-0088: The Vulkan backend
- Status: Accepted (M4 phase 4.1v(a), 2026-11-24; plan approved by the author on 2026-11-24. The conformance suite passes on lavapipe in CI; real GPUs and MoltenVK are re-tested later). Amended by 4.1v(b) (surfaces, the M1 renderer on Vulkan, backend selection; decisions 10–17) and 4.1v(c) (null descriptors, the Linux editor viewport, D4's spike; decisions 18–20), 2026-11-25
- Date: 2026-11-24
- Builds on: ADR-0040 (RHI), ADR-0042 (GPU testing in CI), ADR-0045 (Slang), ADR-0089 (timer scopes); M4 refinement R3 and R4

## Context
Until M4 the engine rendered only on Metal. R3 brings Vulkan into M4, so every rendering feature from 4.3 on lands on both backends, and Linux CI can finally run the GPU tests that it has skipped since M1 (ADR-0042). The RHI was designed for this: command lists as data, sync2-style barriers, bindless indices, `Backend::Vulkan` and SPIR-V shader sources. The Metal backend relies on two things Vulkan does not give for free: tracked hazards, and argument buffers that hold 16 384 device pointers.

## Decision
1. **A new crate, `concordia-rhi-vulkan`, on `ash`** (MIT OR Apache-2.0), loaded at run time (`ash`'s `loaded` feature). It builds on every OS. Without a Vulkan loader or a suitable device, every entry point returns `RhiError::NoDevice`.
2. **The `unsafe` exception (R4).** Raw Vulkan calls are `unsafe`, and they stay inside this crate, as Metal's stay inside `concordia-rhi-metal`. Every block has a `// SAFETY:` comment, enforced by `#![deny(clippy::undocumented_unsafe_blocks)]`. Conversion, SPIR-V checks, caps and hazard planning are safe code.
3. **Vulkan 1.3 core is the floor:** dynamic rendering, synchronization2, timeline semaphores, descriptor indexing and buffer device addresses. lavapipe, MoltenVK and current desktop drivers meet it. A device below it is `NoDevice`, with the missing features named.
4. **Bindless on Vulkan:**
   - Set 0 binding 0 is a storage buffer of buffer device addresses. Under `CONCORDIA_SPIRV`, which `concordia-shaders` defines for SPIR-V, `bindless.slang` declares it as `StructuredBuffer<uint*>`. A std140 uniform block of 16 384 pointers would be 256 KiB, over common uniform-buffer limits. Shaders are unchanged, and so is the Metal output.
   - Set 1 holds sampled images (binding 0) and the four immutable static samplers (binding 1); set 2 holds storage images.
   - The sets are update-after-bind and partially bound. One pipeline layout per device carries 128 bytes of push constants for every stage.
5. **Memory through `gpu-allocator`** (MIT OR Apache-2.0). A heap is one dedicated allocation, and placed textures bind at an offset in it.
6. **Hazards are the backend's job**, as Metal's tracked mode makes them on Metal:
   - Every texture has a home layout chosen from its usage, and each step (render pass, dispatch, copy) moves what it uses out of that layout and back.
   - A global memory barrier separates consecutive steps. New textures move to their home layouts at the start of the next submission.
   - RHI barriers are still translated (aliasing discards from `Undefined`).
   - Making the render graph's barriers authoritative, and dropping the global barriers, is a later performance change.
7. **Metal's conventions:**
   - Clip-space Y points up (a negative-height viewport), and `CullMode::Back` keeps counter-clockwise triangles.
   - Every `QueueKind` runs on one universal queue for now.
8. **Timer scopes (ADR-0089)** use timestamp queries, one pool per timed submission. Granularity is `draw_boundary` when the queue has timestamp bits.
9. **Tests:**
   - The RHI conformance suite runs unchanged, plus Vulkan-only cases.
   - Linux CI runs them on Mesa's lavapipe with the Khronos validation layers in a `vulkan (lavapipe)` job of its own workflow (`vulkan.yml`, keeping `ci.yml` fast per ADR-0071), run on demand (`workflow_dispatch`; author decision 2026-11-25). Any error-severity validation message fails the test.
   - `CONCORDIA_REQUIRE_VULKAN=1` turns a missing device or layer into a failure; `CONCORDIA_REQUIRE_GPU` keeps meaning Metal.
   - Slang's SPIR-V keeps source entry names (`-fvk-use-entrypoint-name`), and Slang vertex shaders need `shaderDrawParameters`, which the backend requires.
   - RHI goldens are shared across backends, with one tolerance file.

10. **Surfaces and swapchains (4.1v(b)).** `SurfaceTarget` gains `Xlib`, `Xcb`, `Wayland` and `Headless` (`VK_EXT_headless_surface`, for presenting in CI without a window); `MetalLayer` is reused by MoltenVK through `VK_EXT_metal_surface` (wired, untested). Metal refuses the new targets with `Unsupported`. The instance enables `VK_KHR_surface` and every platform surface extension the loader has. A pure planner picks two images when the surface allows (like Metal), checks the extent and usage, and uses FIFO; acquire rebuilds an out-of-date or resized swapchain; images rest in `PRESENT_SRC`. `on_presented` fires when the frame's GPU work retires, an approximation until `VK_KHR_present_wait`.
11. **sRGB over UNORM.** A surface that offers only UNORM formats (Mesa's headless one) presents sRGB through `VK_KHR_swapchain_mutable_format`: the swapchain is UNORM with an sRGB view list, and the renderer writes through sRGB views, so its output matches Metal's.
12. **The retire thread.** Lazy retirement held a presented frame's GPU time and presentation until the next device call, so an idle viewport never reported its last frame. A thread now polls the progress timeline (every millisecond while work is in flight) and retires finished submissions, firing callbacks as Metal's completion handlers do. It makes no Vulkan call outside the state lock. (4.1v(b) moved it there believing that waiting on the timeline while another thread submitted crashed the validation layer; the crash continued and was in fact lavapipe's per-pixel texture choice, decision 18. Polling under the lock was kept: it is simple and costs at most a millisecond.) It is joined on drop.
13. **Strict validation.** `CONCORDIA_VULKAN_VALIDATION` is `off` (default), `auto` (the layer when installed), `on` (required) or `strict` (required, and any error-severity message makes the device's next submit, present, wait or read fail with the messages). Render tests that never see the device still fail on validation errors. The `vulkan` workflow sets `strict`.
14. **Backend selection.** A new crate, `concordia-rhi-select`, is the one place that turns `auto|metal|vulkan` into a device, a probe or a probe record. `CONCORDIA_BACKEND` overrides the project's `[render] backend`, which overrides `auto` (Metal on macOS, Vulkan elsewhere); an unknown value is an error. Every device call site goes through it, and `concordia gpu-probe` takes `--backend`.
15. **Per-backend golden tolerances (D4).** `tolerances.ron` gains an optional `backends: { "vulkan": (default: …, goldens: {…}) }`. Most specific wins: the backend's golden entry, the shared golden entry, the backend's default, the shared default. Vulkan compares against the goldens blessed on Metal and never blesses; its failures go under `<suite>/vulkan/`. `CONCORDIA_GOLDEN_KEEP=1` also writes comparisons and scores for passing checks, for review pages.
16. **The SPIR-V pointer rule.** A function-storage variable holding a physical-storage-buffer pointer must be decorated `AliasedPointer` or `RestrictPointer` (VUID-VkShaderModuleCreateInfo-pCode-08737). Slang omits the decoration when it spills a pointer field, so the backend refuses such modules with a named reason (`check_spirv_module`), and shaders keep table indices rather than pointers in structs passed to generics. Render tests check every entry point's SPIR-V on any OS.
17. **Windows outlive their surfaces.** The platform sends `WindowEvent::Closing` before it destroys a window, and `concordia run` calls `concordia_render::detach_surface` then, so a surface never outlives its window. `concordia run` attaches X11 and Wayland windows through one `unsafe` block, the twin of the macOS one (approved, 4.1v(b) Q2).
18. **Empty texture slots show a fallback texture, and per-pixel texture choice is avoided (4.1v(c)).** Reading a partially-bound descriptor that was never written, or whose view was destroyed, is undefined in Vulkan, whereas Metal reads its nil entries as zero. The backend creates a 1×1 texture at device start (cleared to zero, resting in `General`) and points every empty slot of both texture sets at it, the unused set of a texture with one usage, and freed slots; a shared conformance case checks a freed and a never-written slot read zero. (Null descriptors from `VK_EXT_robustness2` were tried first; a real descriptor needs no extension and no driver's null handling.) Separately, two glTF goldens crashed lavapipe in its non-uniform sampling loop: the prefiltered environment levels are separate textures picked per pixel by roughness, and lavapipe faulted when neighbouring pixels read different textures, though every index was valid and every slot held a real texture (likely a lavapipe bug; to report). `env_sample` therefore loops over the levels with a uniform index and samples only the pixel's own (pixel-identical on Metal), and sentinel indices (`NO_TEXTURE`) are clamped into the table (`in_table`). Shaders should avoid picking a different texture per pixel where a uniform loop or one mipmapped texture can do; the shadow cascades (`frame.shadow_tex[c]`) still do, and pass on lavapipe.
19. **The editor's viewport on Linux (4.1v(c)).** The Tauri editor (GTK 3, WebKitGTK) attaches an X11 child window of its window, on its own XCB connection (x11rb, safe API), as a `SurfaceTarget::Xcb`, placed at the page's slot. The child selects no input, so mouse events reach the page under it, which drives the camera and grabs the gizmo (`__CONCORDIA_NATIVE_INPUT__` is true only on macOS). GTK's `unrealize` signal, which runs before the window's X11 window is destroyed, detaches the surface and then destroys the child. The existing `attach_surface` block serves both platforms, so the editor gains no `unsafe`. The child sits above the webview inside the slot (on macOS the webview is on top), so page overlays inside the slot are hidden on Linux. Wayland embedding needs GTK's `wl_display` through an `unsafe` foreign-display call, which is not approved: under Wayland the page renders the viewport, and `GDK_BACKEND=x11` (XWayland) gives the native one.
20. **D4's spike (4.1v(c)).** On the CI runner's lavapipe (Mesa 25.2.8, LLVM 20.1.2, Vulkan 1.4.318, validation layers 1.3.275), Slang 2026.22's SPIR-V for a mesh shader (`MeshEXT`), an amplification shader (`TaskEXT`) launching it, and a compute shader with an inline ray query (`RayQuery`, one-triangle BLAS/TLAS) compiles, passes the backend's checks, and runs correctly with no validation errors. So 4.3b's mesh-shader path and 4.8's ray queries can be tested on Linux CI directly; the compute fallbacks D4 names are still needed for MoltenVK, which has no mesh shaders. The spike is test-only (`concordia-rhi-vulkan/src/spike`); `concordia-shaders::Stage` gains `Mesh` and `Amplification`.

## Consequences
- Linux CI exercises GPU code for the first time, in software. lavapipe is slow, so the Vulkan suites run small images.
- Real GPUs (the author's Linux machine, MoltenVK on the Mac) are tested later. A driver difference that lavapipe hides may surface then.
- Global barriers between steps cost GPU time on real hardware; they buy correctness now, and the render graph's barriers can replace them.
- `bindless.slang` has one target switch. Any new global table must be checked on both targets (`spirv_bindless_tables_use_sets_0_1_2`).
- Linux CI renders goldens for the first time, within per-backend tolerances; the M1 gate golden passes within its shared tolerance.
- A shader that reads an empty bindless slot gets zero on both backends rather than a crash on one; a renderer bug that reads the wrong slot shows as a wrong image, not a fault. A sentinel index (`NO_TEXTURE`) must be clamped before it reaches a table.
- `env_sample` costs a short loop over the prefiltered levels; storing them as one mipmapped texture would remove it but changes the IBL images (a re-bless), so it waits for a phase that touches IBL.
- The Linux editor's viewport covers page overlays inside the slot, and has no native gizmo grab or latency benches; Wayland sessions fall back to the page-rendered viewport.

## Alternatives considered
- **wgpu:** another abstraction under ours, without bindless arrays of the size we need or the barrier control later phases want. Rejected.
- **vulkano:** safe wrappers, but its synchronisation model would fight the RHI's command lists. Rejected.
- **Our own allocator:** less code to depend on, but sub-allocation, alignment and memory-type selection are easy to get subtly wrong. `gpu-allocator` is widely used and permissively licensed.
- **Requiring explicit barriers everywhere:** Metal ignores them, so nothing would test them until a real Vulkan renderer existed. Tracking in the backend keeps the conformance suite unchanged.
- **A scalar-layout uniform buffer for the table** (`-fvk-use-scalar-layout`): 128 KiB, still over the 64 KiB limit on some drivers. Rejected.
- **Null descriptors in empty slots** (`VK_EXT_robustness2`'s `nullDescriptor`): simpler, but they need the extension and depend on each driver's null handling; replaced by the fallback texture in 4.1v(c).
- **Waiting on the timeline in the retire thread** (`vkWaitSemaphores` outside the lock): lower latency; dropped in 4.1v(b) on a misdiagnosed crash (see 12). It could come back with the perf work.
- **The editor presenting into the whole Tauri window**, or sharing GTK's Xlib `Display`: GTK draws into the same window, and GTK's display is not ours to keep alive. A child window on our own connection has a clear owner and lifetime.
