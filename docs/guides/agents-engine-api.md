# Concordia Engine API: guide for agents

The Engine API is how every client (agents, the CLI, the editor, tests) drives the engine. Over MCP the same methods appear as tools named with `_` instead of `.` (`entity.spawn` → `entity_spawn`). Everything here works headless and needs no API key.

## Workflow
1. `session.open {"client": "claude-code", "actor": "agent:claude-code"}` sets the default actor for this session. (The MCP server does this for you.)
2. `scene.new {"path": "scenes/arena.scene.ron", "name": "Arena"}` or `scene.open {"path": ...}`.
3. Discover shapes with `schema.get {}` (index), `schema.get {"name": "Transform"}` (component) or `schema.get {"name": "entity.spawn"}` (method). The index's `components` list gives each component's `category`, a one-line `description` and whether it is `addable`; a component's schema carries its `default`.
4. Edit with `entity.spawn`, `component.add` (the default value, then patch what differs), `component.set` (whole value), `component.patch` (merge patch, e.g. `{"scale": [2, 2, 2]}`), `component.remove`, `entity.despawn`. Group edits with `txn.begin {"label": ...}` … `txn.commit {"txn": ...}` so they undo as one step.
5. Check your work with `entity.get`, `component.get` and `query.run`.
6. `scene.save {}` writes canonical RON. `txn.undo` / `txn.redo` work across restarts when the file is unchanged. `txn.history` shows who changed which entities and when; `txn.undo_to {"txn": ...}` rewinds back to and including a commit.
7. Simulate without touching the scene: `sim.step {"ticks": 60}`, then read with `"world": "play"`; `sim.stop {}` discards the play world.

## Building a scene (M1)
1. Look around: `project.files {}` lists the project's files with their kind and import status.
2. Bring in a model: `asset.import {"path": "models/crate.glb"}` (glTF `.gltf`/`.glb` or `.fbx`), then `prefab.instantiate {"asset": "asset:<id>", "translation": [0, 0, 0]}` (one undo step). Both formats give the same sub-assets: `mesh/<mesh>/<part>`, `material/<name>` (one slab each), `texture/<name>`, `skin/<index>` and `clip/<name>`. FBX files are converted to meters, Y-up while importing, and each animation stack becomes a clip starting at 0; a missing external FBX texture is skipped with a warning in `log.tail`.
   - Static meshes with more than 8,192 triangles (all parts of a mesh together) also get meshlets for GPU culling; `"meshlets": true` or `false` in the sidecar's settings forces it (`true` refuses skinned meshes). `asset.meshlet_stats` (`{"asset": "asset:<id>"}`, or one sub-asset) reports each mesh's meshlets (count, triangles and vertices per meshlet, bounds, normal cones) or why it has none; `concordia cluster stats <file>` prints the same.
3. Add ready-made entities: `entity.templates {}` lists them; `entity.create {"template": "Cube", "translation": [0, 0.5, 0]}`, `{"template": "Directional Light"}`, `{"template": "Camera"}`. Group with `"parent"`, copy with `entity.duplicate`, regroup with `entity.reparent`. For physics, `component.add` `RigidBody` and `Collider` (a 1 m box by default), then `component.patch` the shape; for a sky, `entity.spawn` an entity with `Environment` (no `Transform` needed) and an imported `.hdr` as its `map`; sky light is scaled by the camera's exposure, so under daylight exposure (EV 15) its `intensity` is in the thousands. Materials are `.material.ron` files (see Materials below): write one with `material.set` and set the returned id as a `MeshRenderer`'s `material`. (`entity.spawn` still takes raw components.)
4. Look at it: `capture.screenshot {}` returns an image (768 × 432 by default; pass `width`/`height` for detail, `camera` or `view` to choose the viewpoint, `"world": "play"` to see the simulation, `view_mode` for a debug view such as `"wireframe"`, `"normals"`, `"overdraw"` or `"light_clusters"`). `render.stats {}` then reports that frame's cost (draws, triangles, CPU and GPU ms, GPU memory) and the materials simplified to fit the closure budget: use it to find what makes a scene slow or why something is missing. With temporal anti-aliasing on (`[render] temporal`, or `render.set_temporal` for the session), a capture renders its still pose a whole jitter cycle first, so it is converged (`temporal_frames` overrides the count). `viewport.pick` tells you which entity is at a pixel of that image; `viewport.drop` where something placed there would land.
   - The truth to compare with (M4 4.1b4, ADR-0090): `capture.reference` (e.g. `capture.reference {}`) path-traces the same view (384 × 216 at 64 samples per pixel by default: a noisy preview in seconds; `spp`, `seed`, `max_bounces`, `camera`/`view`, `"backend": "auto"|"gpu"|"cpu"`). It is capped at 1280 × 720 × 64 samples per call; the error says to lower the size or samples, and full-quality references are blessed with `just bless-reference`. It traces meshes, materials with their color, emission, metallic-roughness and mix textures, lights and the sky; normal maps, skinning and particles are not traced.
5. Run it: `sim.step {"ticks": 120}`, `input.inject` to press actions, `physics.raycast` to probe, then read with `"world": "play"`.
6. `scene.save {}`.

## Templates, spawners and crowds (M2)
- A template is a `templates/**/*.template.ron` file (named by its file stem) or a module built-in. It composes **traits** (Rust-defined, configured by parameters, e.g. `"Movement": (velocity: (0.0, 0.0, 2.0))`) and plain **component** values, which override what traits add. Two traits adding the same component is an error naming both. `entity.templates {}` lists every template with its traits, components and any `problem`; `schema.get {"name": "Movement"}` shows a trait's parameters.
- One entity in the edit world: `entity.create {"template": "goblin"}` (one undo step).
- Many entities in a level: add a `Spawner` to an entity, `component.set {"entity": <id>, "component": "Spawner", "value": {"template": "goblin", "count": 200, "seed": 1, "distribution": {"Disc": {"radius": 20.0}}}}`. The scene keeps only the spawner; its entities appear, deterministically, when play starts (`Grid {spacing}`, `Box {half_extents}` or `Disc {radius}`, around the spawner's transform).
- Many entities right now, for a test: `terra.spawn_batch {"template": "goblin", "count": 1000, "seed": 2}` spawns into the play world (never the scene, never journaled); `terra.despawn_batch {"with": ["Hostile"]}` clears them.
- Far crowds can also be drawn more cheaply (representation LOD, ADR-0076): `Representation {instanced: Some({mesh, material}), instanced_from: 40.0, hidden_from: 150.0}` (a component, also allowed in a template's `components`) draws the cheaper mesh, unskinned, from `instanced_from` meters from the camera, and nothing from `hidden_from`. Each capture or viewport chooses for its own camera every frame; it never changes the world or its hash. A character's cheaper mesh stands for all its parts; hidden entities cast no shadow and aren't picked. `capture.screenshot {"view_mode": "lod"}` shows both kinds of LOD: hue from the simulation level (white: none; green, yellow, orange, red: levels 0–3), instanced at half brightness, hidden not drawn.
- Far crowds can tick less often (simulation LOD, ADR-0076): add the `Lod` trait (`"Lod": (distances: (20.0, 60.0, 120.0), rates: (2, 4, 8), hysteresis: 3.0)`) and tag the player or a scene camera rig with `LodViewer` (`component.set {"entity": <id>, "component": "LodViewer", "value": null}`). Levels 1–3 start at `distances` from the nearest viewer and update every `rates` ticks (level 0 every tick); detail comes back only `hysteresis` meters inside a boundary. The render camera never counts, and with no viewer everything is full detail. Far characters' animation follows it, and their clip events still fire once.
- Check what Terra did: `terra.stats {"world": "play"}` (counts, skipped commands, the schedule's phases and parallel waves, and `lod`: viewers, entities per level, due this tick) and `terra.inspect {"entity": <id>, "world": "play"}` (archetype, chunk, each component's storage kind: dense, shared or tag, and pending signals).

## Playtest assertions (M3 3.2, projects with `[replay]`)
- `assert.eval {"assertions": ["within 600 ticks: distance(tag(\"player\"), tag(\"door\")) < 2m"], "source": "replay", "path": "tests/replays/walk.replay.ron"}` decides each assertion tick by tick over the replay's inputs on a fresh play world. `source: "scenario"` runs a `tests/playtests/<name>.playtest.ron` (`Playtest(scene, max_ticks, inputs: [(tick, event)], replay?, assertions)`) on its scene, which must be open; `source: "live"` (default) checks the condition on the current play world now, changing nothing.
- The language (ADR-0084): `within N ticks|Ns`, `always [for …]`, `never [for …]`, `eventually`, `at …`, `after …, <when>`; conditions with `< <= > >= == !=`, `and`, `or`, `not`; `distance(a, b)`, `count(sel)`, `exists(sel)`, `event("Signal")`, fields `name("Crate").Transform.translation.y`, `any(sel).…`, `all(sel).…`; selectors `tag`, `name`, `id`, `with`; units `m`, `s`, `ticks`, `deg`. Parse and type errors (unknown components or fields with suggestions, unit mismatches, a `tag`/`with` field without `any`/`all`) are `InvalidParams` naming the assertion.
- Each result: `status` (`passed`, `failed`, `undecided`, `error`), `decided_at`, and `witness` (the comparison's left side; a `within` that ran out adds `closest` and `closest_at`). CLI: `concordia assert eval <text> --replay <file> [--json]` (exit 0, 1, 2) and `concordia test playtests`.

## Generated content (M3 3.7, projects with `[gen]` and `[assets]`)
- `gen.list` lists the providers (`id`, `kind`, `version`, `extensions`, `procedural`, and the JSON Schema of each `request`).
- `gen.run {"provider": "mesh", "request": {"Cylinder": {"radius": 0.25, "height": 3.0, "segments": 12}}, "seed": 1, "path": "assets/models/pillar.glb", "actor": "agent:modeler"}` writes the file, imports it (its `id` and `sub_assets`, as `asset.import` returns) and records its provenance in the sidecar, so the same request and seed make the same bytes. It needs an actor; Studio holds `path` to the role's write paths.
- Meshes (`mesh`, `.glb`, meters, +Y up): `Box {size}`, `Sphere {radius, segments, rings}`, `Capsule {radius, height, segments, rings}`, `Cylinder {radius, height, segments}`, `Torus {major, minor, segments, sides}`, `Extrude {profile, depth}` (a polygon in XY along +Z), `Lathe {profile, segments}` ((radius, y) points around Y), `Heightfield {size, cells, amplitude, frequency}` (seeded), `Sdf {shapes: [Sphere {center, radius} | Box {center, half}], smooth, cell}` (surface nets), `Rock {size, detail, roughness, strata, lumps}` (seeded lumps, 3D noise and ledges; `detail` grid cells across, 8–250) and `CanyonTile {tile, of, cells}` (a strip of the canyon seeded by the seed, `concordia_gen::canyon`); rocks and canyon strips always get meshlets (M4 4.4c).
- `gen.restore {"actor": "tool:perf"}` remakes every generated file that is missing or whose bytes differ from the BLAKE3 its sidecar records (`provenance.output`, which `gen.run` writes), from the recorded recipe, and lists them as `restored`, `unchanged` and `skipped` (non-procedural providers). A recipe that no longer makes its recorded bytes is an error naming the file. So large generated files can stay out of git (M4 4.4c: `examples/m4-canyon`).
- Sound effects (`sfx`, `.wav`): `{"preset": "jump", "pitch_sweep": 1.4, "duration_ms": 220}` (presets `pickup`, `hit`, `jump`, `explosion`, `ui_click`; `base_hz`); peaks at −1 dBFS; the seed varies noisy presets.
- Music (`music`, `.wav`): `{"bpm": 96, "beats_per_bar": 4, "bars": 8, "loop_from_bar": 0, "tracks": [{"instrument": "Pluck", "volume": 0.8, "notes": [{"beat": 0, "beats": 1, "pitch": 60}]}]}` (instruments `Sine`, `Square`, `Saw`, `Pluck`, `Kick`, `Snare`, `Hat`); the loop points go into the sound's import settings.
- Textures (`texture`, `.png`): `{"size": 256, "pattern": {"Noise": {"kind": "Value", "cells": 8, "octaves": 4}}, "colors": [[40, 40, 44, 255], [120, 118, 110, 255]]}` (also `Worley`, `Checker {cells}`, `Stripes {count}`); noise tiles seamlessly.
- Blender (`blender`, `.glb`, not procedural): `{"script": "assets/blender/scripts/pillar.py", "timeout_s": 120}` runs a project script in the user's own Blender (4.2+, found through `[gen.blender] path`, `BLENDER_PATH` or the default install) with `bpy` and `SEED` in scope, then exports glTF. `info` lists `objects` (name, type, triangles, dimensions), `actions` (each becomes a `clip/<name>` sub-asset), the Blender version and `script_hash`. A failure returns Blender's exit code and traceback; a run past `timeout_s` is killed. In Studio the script must be inside the role's write paths.
- Plugins: `[[gen.plugin]]` (`id`, `kind`, `extensions`, `command`, `timeout_s`) adds providers that run as their own programs (JSON `{request, seed, out}` on stdin); none load unless listed (ADR-0085).

## Tags (M3)
- `Tags` is a built-in component: a list of words, e.g. `"Tags": ["player", "hero"]`. Playtest assertions select entities with `tag("player")` (M3 3.2).

## Replays (M2, projects with `[replay]`)
- Record: `replay.record {"path": "tests/replays/jump.replay.ron"}` starts a fresh play world from the open scene; drive it with `input.inject` and `sim.step` (or `sim.play`); `replay.record {"action": "stop"}` writes the file. It holds the input changes per tick (after binding, so rebinding keys doesn't break it), every tick's world hash, and full checkpoint hashes every `checkpoint_every` ticks (default 60). `"task": "T-0001"` names the task it is evidence for. Format version 1 (M3 3.1a); version 0 files still run.
- Check: `replay.run {"path": ...}` replays it headless on a fresh play world and compares every checkpoint. `ok: true` proves the same behavior; otherwise `divergence` names the exact first `tick` that differs, the `last_matching_tick`, and, at the next checkpoint (`parts_tick`), the `parts` that differ (component names, `@entities`, `@clock`, `@rng`, `@signals`) and the `fields` (entity, component, path, expected, actual) from stills kept in `.concordia/ddc` (`"stills": false` on record leaves them out; `fields_note` explains an empty list). The play world stays at the end for `"world": "play"` reads.
- `mode: "resimulate"` replays the inputs on the current code and returns new `checkpoints` (prove a fix); with `"update": true` it rewrites the file (re-bless). `mode: "ab"` with `"other": "<project dir>"` runs the replay here and on the other project's build in lockstep and reports the first differing tick, its fields and the `suspect_system` (the system or `<Phase> commands` after which they first differ). A replay recorded with another platform, manifest, scene, seed, tick rate, engine, script build, input map or template set is refused with `ReplayMismatch`; `"force": true` runs it anyway and lists the `mismatches`.
- Nothing about replays is journaled or changes the scene. CLI: `concordia replay record <path> --ticks N [--inputs events.json]`, `concordia replay run <path> [--threads N] [--force]`, `concordia replay migrate <path>` (version 0 → 1), `concordia replay diff <a> <b>` (header fields, the first differing input and tick, parts and fields; exit 1 if they differ), `run --mode resimulate --update`, and `run --mode ab --other <dir>`.

## Input and sensors for gameplay (M2, 2.10a)
- **Scripts read input through a component.** Give the player entity `InputActions {"watch": ["move", "light"]}`; every tick `input.actions` fills its `states` (`{pressed, just_pressed, just_released, value}` per watched action; unknown names are absent). While the in-game UI holds the keyboard or pointer, those actions read as released with a zero value. A script reads it in `PrePhysics` after `input.actions` (or later) and writes `CharacterMotion`; check with `component.get {"entity": id, "component": "InputActions", "world": "play"}` after `input.inject` and `sim.step`.
- **Sensors see characters.** A `Collider` with `is_sensor` raises `ContactBegan {other, sensor}` / `ContactEnded` on both entities the tick after they touch: dynamic and kinematic bodies, and characters (`CharacterController`) too. Two sensors never report each other, and a collider sits at its own entity's `Transform` (parents don't move it). Gameplay scripts receive both signals by name (2.10c.1).

## Materials (M2, projects with `[assets]`)
- A material is named **nodes** plus a **root** (ADR-0068). A node is a `Slab` (one BSDF closure: base color, metallic, specular, roughness, textures, emission, `transmittance`, and the optional `haze`, `fuzz`, `subsurface` and `thin_film`) or an operator over other nodes by name: `Vertical {top, bottom}` (layering, e.g. a clear coat), `Horizontal {a, b, mix, mix_texture}` (side by side) or `Coverage {node, coverage}`. Every node must be used by the root. `schema.get {"name": "Material"}` lists every field and range.
- Read: `material.get {"path": "assets/materials/steel.material.ron"}` → `{material, migrated, id}`. M1's flat files read as one slab named `surface` with `migrated: true`; saving rewrites them as layered text.
- Write: `material.set {"path": ..., "material": {...}}` (the whole material; the file is created if missing). It validates, writes canonical text, imports it and returns `{id, written}` (`written: false` if nothing changed); the renderer draws the new content on the next frame. An invalid material is refused with `InvalidParams`, naming the `node.field` (`data.field`, `data.node` and a pointer into the params).
- Like `asset.import`, it changes a file, not the scene: it is attributed in `log.tail` ("material saved", with the actor) and is not undoable. In the Studio, the path must be inside the role's write paths.
- Cost: each slab use is one closure; a material over the platform's `closure_budget` is simplified and listed in `render.stats` `downgraded_materials`. `capture.screenshot {"view_mode": "closures"}` shows the count per pixel.

## Animation (M2, projects with `[anim]` and `[assets]`)
- Imported glTF and FBX models with skins give their mesh entities `Skinned {skin: "asset:<id>#skin/<n>"}`; their clips are sub-assets `asset:<id>#clip/<name>` (`asset.list` shows them).
- Play one: `prefab.instantiate` the model, then `component.set` `AnimPlayer` `{"clip": "asset:<id>#clip/<name>"}` (optional `time`, `speed` (default 1, negative plays backward), `looping` (default true)) on the entity with `Skinned`. A model with several materials has one `Skinned` entity per mesh part; play the topmost one (`query.run {"with": ["Skinned"], "select": ["Name", "Parent"]}`: its `Parent` isn't another `Skinned` entity), and the parts under it follow its pose. The clip may come from another file if its bone names match (an animation-only download).
- Playing (`sim.step`/`sim.play`), the play world's entity gets a `Pose` (`bones`: each joint's local transform, in skin order) and `AnimPlayer.time` advances at the fixed step (scaled by the time scale). Read both with `component.get` and `"world": "play"`; poses are part of the world hash, so replays check them.
- Rendering: `capture.screenshot {"world": "play"}` (and the viewport while playing) draws each character in its current pose, skinned on the GPU, with skinned shadows; the viewport blends poses between ticks. The edit world has no poses, so it draws the bind pose. An extra mesh part of a model follows its parent's pose.
- The clips a play session can use are loaded when play starts: every clip in the same file as a player's clip, and every clip a graph names. Anything that fails to load is logged (`log.tail`, target `concordia::anim`) and that character holds its pose. Nothing about animation is journaled or changes the scene.
- Graphs (blend trees and state machines, Godot `AnimationTree` semantics): write an `.animgraph.ron` file and `asset.import` it (`schema.get {"name": "AnimGraph"}` gives its shape). It names its `parameters` (`Float(default)`, `Int(default)`, `Bool(default)`, `Trigger`), its `nodes` and its `root`:
  - `Clip(clip: "asset:<id>#clip/<name>", looping)`;
  - `Blend2(a, b, amount, filter)`, where `amount` is a float parameter from 0 to 1, and a non-empty `filter` lists the bones blended;
  - `BlendN(inputs, weights)`, one float parameter per input, normalized by their sum;
  - `OneShot(base, shot, request, fade_in, fade_out, curve, filter)`: the `request` trigger plays `shot` once over `base`, and the fade-out ends at the shot's end;
  - `TimeScale(input, scale)`;
  - `Transition(inputs: [(node, reset)], select, xfade, curve)`: an int parameter picks the input;
  - `StateMachine(states: {name: node}, start, transitions)`. Each transition has `from` and `to`; `switch`: `Immediate`, `Sync` or `AtEnd`; `advance`: `Disabled`, `Enabled` (travel only, the default) or `Auto` (when its bool or trigger `condition` holds); and `xfade`, `curve` (`Linear` or `Smooth`), `reset` and `priority` (lower is preferred).

  Nodes refer to each other by name; each node has one parent, and errors name the node.
- Play a graph: `component.set` `AnimGraphPlayer` `{"graph": "asset:<id>"}` on the entity with `Skinned`. Its `floats`, `ints` and `bools` maps set parameters; missing ones use the graph's defaults. `triggers` (names) and `travel` (`{machine node: target state}`) are one-tick requests, cleared after each evaluation. Travel takes the fewest transitions that aren't disabled, and jumps straight there when there is no path. If an entity also has an `AnimPlayer`, the graph plays.
- While playing, the play world's entity also gets `AnimGraphState` (per node, in name order: clip times, the current and fading state or input, fade progress, the travel path). It is hashed simulation state; don't edit it.
- Steer a running game: `component.patch {"entity": <id>, "component": "AnimGraphPlayer", "patch": {"bools": {"moving": true}}, "world": "play"}` (or `"patch": {"travel": {"moves": "idle"}}`). The next `sim.step` tick sees it. Graph files edited during play apply at the next play.
- Inspect a character while playing: `anim.inspect {"entity": <id of the Skinned entity>}` → every bone's `local` (the pose), `model` (relative to the model's root) and `world` transform; the `clip` player (time, `frame` when the clip has a frame rate, events) or the `graph` (each node's playback with state and input names, every parameter's effective value); and `pending_events` (raised last tick, delivered next tick). `NotPlaying` before `sim.step`. There is no `anim.set_param` or `anim.travel`: use `component.patch` with `"world": "play"` as above.
- Clip events (2.4.4): add them in the model's import sidecar (`<file>.import.ron`), then `asset.import` the file again: `settings: {"clip_events": {"<clip name>": [{"time": 0.25, "name": "step"}]}}` (seconds from the clip's start; errors name the clip and event). While playing, a step that crosses one raises an `AnimEvent` signal on the character (`name`, `clip`, `node` for graph clips, `time`, `weight` = the clip's share of the pose), delivered to gameplay on the next tick. A step covers [from, to) (backward: (to, from]); a clamped clip reaching its end covers the end; looping clips fire once per lap; time scale 0, speed 0 and seeks fire nothing. Inside graphs, every clip with a share above 0 fires (as in Godot): a blend's inputs split the share, a filtered blend keeps its first input at full share, and a cross-fade gives the fading-out state the rest.
- Imported emission (M4 4.1b4, ADR-0102): emission is luminance in nits. A model's emissive values are taken as screen brightness at a reference exposure, `"emissive_reference_ev100"` in its sidecar's `settings` (null: the project's main scene camera EV), converted with × 1.2 · 2^EV; set it and `asset.import` again when a model was authored for another exposure.
- Attach an item to a bone: an entity with `Parent` = the `Skinned` entity and `BoneAttachment {"bone": "<bone name>"}` (Godot's `BoneAttachment3D`); its `Transform` follows the bone every tick, so its children (the sword) follow too. A missing bone leaves it in place and logs once.
- Tween any number field: `Tweens {"tweens": [{"component": "Transform", "field": "/translation", "to": [0, 2, 0], "duration": 0.5, "transition": "Quad", "ease": "Out"}]}` on the entity (JSON pointer `field`; a number or array of numbers; optional `from`, `delay`). Transitions and eases are Godot's (`Linear`, `Sine`, `Quint`, `Quart`, `Quad`, `Expo`, `Elastic`, `Cubic`, `Circ`, `Bounce`, `Back`, `Spring`; `In`, `Out`, `InOut` (default), `OutIn`). Tweens run at the fixed step (time scale 0 holds them), the last one on a field wins, a finished one writes its target exactly and is removed, and they die with their entity.
- See the skeletons: `capture.screenshot {"world": "play", "skeleton": true}` draws every posed skeleton's bones over that image (2.4.5), whatever the editor's overlays are; the editor's `viewport.overlays {"skeleton": true}` turns the same drawing on in the viewport and in captures with `overlays: true`. Selection boxes follow the pose.
- In the Studio, the animator (`concordia-animation-graphs`) builds graphs under `assets/anim/`, tries them in preview scenes under `assets/anim/previews/`, and authors clip events in model sidecars; the server lets a role `asset.import` a file whose sidecar it may write.

## Navigation (M2, projects with `[nav]`)
- A navmesh is built inside a `NavMeshVolume` (an axis-aligned box centred on its entity: `half_extents`, `agent_radius`, `agent_height`, `agent_max_climb`, `agent_max_slope_deg`, `cell_size`, `cell_height`, `tile_size`, `edge_max_error`) from the **static colliders** in it: `RigidBody {"kind": "Static"}` with a non-sensor `Collider`. Dynamic and kinematic bodies don't carve it; render meshes aren't a source.
- Mark ground with `NavArea` (a box: `"kind": "Blocked"` or `{"Cost": {"cost": 5.0}}`, cost ≥ 1) and `NavAreaGrid` (`cell_size`, `rows` of `.` keep, `#` block, `o` walkable again; cell (0, 0)'s corner at the entity, rows along +z). Grids apply after areas; walls and blocked cells are kept `agent_radius` away.
- `nav.build {}` (or `{"volume": <id>}`) builds or loads each volume's navmesh and reports `tiles`, `polygons`, `islands` (connected parts: more than the design has means a gap), bounds, `cached` and the cache `key`. Navmeshes are cached in `.concordia/ddc` by their input, and `nav.path` and `nav.build` rebuild only when colliders, marks or settings change.
- `nav.path {"from": [x, y, z], "to": [x, y, z]}` snaps both ends to the navmesh (2 m sideways) and returns corner `waypoints`, `length` and `partial` (the goal is unreachable; the path ends at the closest reachable point). A point with no navmesh near is `ValueInvalid`. With `"world": "play"`, it uses the navmeshes built when play started.
- The walkable surface sits up to one `cell_height` above the floor; compare positions sideways.
- See it: `capture.screenshot {"debug": ["navmesh"]}` draws every polygon colored by island; `viewport.overlays {"debug": ["navmesh"]}` does the same in the editor.
- **Agents (2.5b.1).** A `NavAgent` (`target`, `max_speed`, `radius`, `height`, `path_desired_distance`, `target_desired_distance`, `path_max_distance`, `volume`) walks its entity's `CharacterController` to `target`; the entity needs a `CharacterController`, and nav owns its `CharacterMotion`. Send one in a running game with `component.patch {"entity": <id>, "component": "NavAgent", "world": "play", "patch": {"target": [x, y, z]}}` and read `NavAgentState` (`status`: `Idle`, `Waiting`, `Moving`, `Arrived`, `Failed`; `waypoints`, `next`, `partial`, `planned_for`) with `component.get` or `query.run` (`"world": "play"`).
- Agents plan again when the target moves farther than `target_desired_distance` or they're pushed more than `path_max_distance` off their path; at most `[nav] plans_per_tick` (default 32) plan a tick, longest-waiting first. Arrival and corners are measured sideways, within half the agent's height.
- Signals, on the agent the tick after: `NavArrived {target, position, partial}` (partial: the closest reachable point), and `NavPathFailed {target, reason, detail}` once per target (`NoNavmesh`, `StartOffNavmesh`, `TargetOffNavmesh`, `InvalidAgent`). A size that disagrees with the controller, or is wider than the navmesh's `agent_radius`, warns once in `log.tail`.
- `capture.screenshot {"debug": ["nav_paths"]}` draws each walking agent's remaining path.
- **Click-to-move (2.5b.2a).** `ClickToMove` (`click`: a `Button` action, `pointer`: a `Ray` action, `hold`, `layers`, `max_distance`) on an agent sets its target where a click points: the nearest physics hit, snapped onto the navmesh. Clicking nothing changes nothing. To click like a player: take a pixel of the game camera's image, `viewport.pointer_ray {"x": 480.0, "y": 270.0, "width": 960, "height": 540, "world": "play"}`, then `input.inject` the ray (`PointerRay`) and the button press. New projects' starter map (`input/default.input.ron`) has `move` (left click) and `pointer_ray`, the names `ClickToMove` uses by default, plus the in-game UI's `ui_*` actions. A click the UI took (over a button or panel) never moves the agent. Physics queries in processors see the bodies as of the last step, so clicks count from tick 1.
- **Crowds (2.5c).** A `NavAgent` with a `CrowdAgent` too (`max_acceleration`, `collision_query_range`, `path_optimization_range`, `anticipate_turns`, `optimize_visibility`, `separation`, `separation_weight`, `avoidance`) is steered by the crowd with its neighbours instead: planned in the same budget, it raises the same signals and `ClickToMove` drives it. Without a `CharacterController` it walks the navmesh surface (the crowd moves its `Transform`); with one, the crowd writes its `CharacterMotion`. Every `CharacterController` is solid to surface agents: they step aside and never push it. Avoidance is on by default (`"avoidance": null` turns it off): agents pick velocities that pass their nearest neighbours and nearby navmesh walls. With a `Lod` profile, far agents choose their corners and velocities only on due ticks, but still collide and arrive every tick. Read `CrowdState` (`velocity`, `desired_velocity`, `new_velocity`, `corners`, `neighbours`, `walls`, …) and `NavAgentState.corridor` with `query.run`. Templates add crowd agents with the `Crowd` trait (`agent`, `crowd`). `capture.screenshot {"debug": ["crowd"]}` draws each one's ring, velocities, corners, walls and neighbour links.
- **Traffic (2.5d).** Lanes are entities with a `Lane` (`points` in the entity's space, `speed_limit`, `width`, `next`, `priority`); junctions are entities with a `Junction` listing their connector lanes (connectors that cross or merge are never driven at once; higher `priority` goes first, then whoever waited longest). A `Vehicle` (IDM parameters, optional `destination` lane; usually from a template's `Traffic` trait) is placed on the nearest lane at play, keeps a safe gap, stops at junctions until let in, brakes for crowd members and characters in its lane, and wanders or drives to its destination, raising `VehicleArrived` or `VehicleRouteFailed`. Read `VehicleState` with `query.run`; bad lanes carry `TrafficProblems` in the play world; `capture.screenshot {"debug": ["lanes"]}` draws lanes, junction states and vehicles.
- In the Studio, the level designer (`concordia-navigation`, `concordia-terra-templates` for crowds, `concordia-traffic` for roads) builds and checks navmeshes; the gameplay programmer (`concordia-nav-agents`) walks characters and crowds and checks routes with `nav.path`.

## Audio (M2, projects with `[audio]` and `[assets]`)
- Sounds are imported files: `asset.import {"path": "assets/sfx/hit.wav"}` (`.wav` 8–32-bit integer or float, `.ogg` Vorbis; mono or stereo). The sidecar's `settings`: `gain_db`, `loop_start` and `loop_end` (frames), and `stream` (Ogg only; Ogg over 10 s streams by default).
- A **cue** is a `.cue.ron` file, imported the same way (`schema.get {"name": "Cue"}`): `sounds` (`[(sound: "asset:<id>", weight: 1)]`), `volume_db` and `pitch_semitones` ranges (`(min, max)`), `bus` (default `"SFX"`), `priority` (0–255; higher steals lower), `looping`, `max_instances`, `spatial` (`Some((min_distance, max_distance))`: inverse-distance fade and equal-power pan), and `seed`. Every play draws its sound, volume and pitch from the seed, the entity and the tick, so renders are bit-identical.
- Gameplay asks for sound with **hashed requests**; the voices and the mixer live outside the world and never change a world hash (ADR-0066):
  - `AudioEmitter {cue, playing, volume_db}` on an entity: a looping cue loops while `playing` is true; a one-shot cue plays each time `playing` turns true. Positioned at the entity's `Transform` (parents included) when the cue is spatial. Turning it off, or despawning, stops it with a 5 ms ramp.
  - The `PlayCue {cue, volume_db}` signal on an entity (from processors and scripts; `StopCue {cue?}` stops what that entity started). A signal raised on tick t sounds on tick t + 1. `SetBusGain {bus, gain_db}` sets a bus's gain from gameplay (a volume slider), as `audio.buses` does; it is presentation, so it never changes the world hash.
  - `AnimEventCues {cues: {event name: cue}}` on a character: its clip events (`AnimEvent`) play those cues there.
  - `AudioListener {gain}` on the camera or the player: the lowest-id one is heard (right +x, forward −z). Without one, positioned sounds play centred.
- Buses: Master, SFX → Master and Music → Master by default; `[audio] buses = "<path>.buses.ron"` names a layout (`(buses: [(name, gain_db, mute, send)])`; a cycle, an unknown send or a duplicate is a load error naming the bus). `[audio] voices` (1–256, default 32); `[audio] backend`: `auto` (the default device in `concordia run`, offline everywhere else), `offline` or `none`.
- Headless engines mix **offline**: 48 kHz stereo, exactly 800 frames per tick at 60 Hz, sample-exact. A missing audio device is a warning, and mixing falls back to offline.
- Listen: `audio.render {"cue": "asset:<id>", "seconds": 1.0, "path": "assets/sfx/checks/hit.wav"}` renders a cue alone; `audio.render {}` reports the play world's mix since play started (the WAV keeps the newest 30 s). Both give `frames`, `peak_dbfs`, `rms_dbfs` and a `hash` (equal hashes are bit-identical audio).
- `audio.play {"cue": "asset:<id>", "at": [x, y, z]}` previews a cue outside the world (heard on a device in `concordia run`); `audio.stop {"voice": n}` or `{}` stops voices. `audio.buses {"set": [{"name": "SFX", "gain_db": -3.0, "mute": false}]}` changes buses until the engine closes and reports each bus's peak since the last call. `audio.inspect {}` lists the backend, every voice (cue, entity, bus, gains, position), the listener and the steal, drop and underrun counts.
- See it: `capture.screenshot {"debug": ["audio"]}` draws each positioned emitter's `min_distance` and `max_distance` circles (green while playing), the listener's axes and a line to each playing positioned voice.
- In the Studio, the sound designer (`concordia-sound-design`) imports sounds, writes cues and bus layouts, and wires emitters and clip-event cues; the composer (`concordia-music`) brings finished music as streamed, looping cues on the Music bus; the gameplay programmer raises `PlayCue` from scripts (`concordia-scripting`). New effects come from the synthesizer and new music from scores, both through `gen_run` (`concordia-synthesize-sfx`, `concordia-music`).

## In-game UI (M2, projects with `[ui]`; images, fonts and themes through `[assets]`)
- The UI is entities (ADR-0060). A `UiRoot {canvas, stretch, aspect, z}` tops a tree; its `Parent` children carry `UiNode` (the box: `width` / `height` / `min_*` / `max_*` as `"Auto"`, `{"Px": n}` or `{"Percent": n}`, `margin`, `padding`, `gap`, `grow`, `shrink`, `order`, `visible`, `clip`, `z`) and what they show: `UiText`, `UiImage`, `UiNinePatch`, `UiProgress`, `UiSeparator`. `UiStyle` sets the look (background `Solid` / `Linear` / `Radial` with 2–8 stops, `border`, `radius`, `opacity`, `font`, `font_size`, `weight`, `italic`, `color`); `UiThemed {theme, class}` names a `.theme.ron` class. Colors are linear RGBA.
- **Layout:** a node's `layout` places its in-flow children: `{"Flex": {direction, wrap, justify, align_items, align_content}}` (CSS Flexbox), `{"Grid": {columns, rows}}` (tracks `{"Px": n}`, `{"Fr": n}`, `{"Percent": n}`, `"Auto"`), or `"Stack"` (children fill the box). `"position": {"Anchored": {anchors, offsets, grow_h, grow_v}}` pins a node by Godot's rules (each edge at `anchor × parent + offset`) and lays its own subtree out separately; its size comes from the anchors and offsets.
- **Scaling:** UI space is logical pixels, origin top left, y down. `stretch: "Scale"` maps the root's `canvas` to the viewport by `aspect` (`Keep`, `KeepWidth`, `KeepHeight`, `Expand`, `Ignore`); `"Disabled"` uses the viewport as is.
- **Text:** `UiText {runs: [{text, font?, size?, weight?, italic?, color?, underline}], align, valign, wrap, overflow ("Clip", "Ellipsis"), line_height, max_lines}`. A box never squeezes its text: with the default `"Visible"` overflow, a node grows to its text's height (and, with `"wrap": "None"`, its width), wrapped at the width layout gives it, so a fixed `"height": {"Px": …}` on a stretched label is only a floor; `"Clip"` and `"Ellipsis"` keep the box's size. Unset run fields come from the style, which inherits text fields from the parent. Fonts are assets: `builtin:font/noto_sans`, `builtin:font/noto_sans_mono`, or an imported `.ttf` / `.otf`.
- **Pictures and bars:** `UiImage {image, region?, mode, tint, flip_h, flip_v}` (modes as Godot's `TextureRect`), `UiNinePatch {image, margins, axis_h, axis_v, draw_center}`, `UiProgress {value, min, max, fill, radial, track, bar}` or with `under` / `progress` / `over` textures, `UiSeparator {orientation, thickness, color}`.
- **Themes:** `.theme.ron` (`schema.get {"name": "Theme"}`) maps classes to `base`, `hover`, `pressed`, `disabled` and `focused` styles; a field resolves inline, then the state's style, then the base.
- **Controls (2.7b.2):** `UiButton {action_on}`, `UiToggle {on, look: Checkbox | Switch | Button, group?, allow_none, label_gap}` (a `group` makes radios), `UiSlider {value, min, max, step, orientation, page}`, `UiDropdown {options, selected?, open, max_visible}`, `UiTabs {selected, titles}` (children are pages; only the selected one is laid out), `UiScroll {offset, horizontal, vertical, step, bar_width}` (clips and scrolls its children), `UiTooltip {text, delay_ticks}`, `UiFocus {order?, up?, down?, left?, right?, next?, prev?}` and `UiSounds {hover?, press?, release?, toggle?, change?}` (each raises `PlayCue` on the widget). The engine writes each control's `UiState {hovered, pressed, focused, hover_ticks, item?, grab?, tip?}`; you set `disabled`. Theme state styles follow it (disabled, then pressed, hovered, focused). Signals on the widget, the next tick: `UiPressed`, `UiToggled {on}`, `UiValueChanged {value}`, `UiSelected {index}`, `UiFocusChanged {focused}`.
- **Input:** `ui.interact` runs in the simulation (`PrePhysics`, after `input.sample`, before `nav.click`) from the input map's `ui_pointer`, `ui_click`, `ui_scroll`, `ui_viewport`, `ui_up` / `ui_down` / `ui_left` / `ui_right`, `ui_accept` (Enter, Space), `ui_cancel` (Escape), `ui_next` (Tab), `ui_prev` (Shift-Tab), `ui_page_up` and `ui_page_down` actions (new projects' starter map has them), so replays reproduce every click. A press over a widget presses and focuses it; a button fires on release over the same widget; sliders follow drags; the wheel scrolls the innermost `UiScroll` by `step` per line (`Scroll` events are in lines; the windowed player turns a trackpad's pixels into lines at 20 logical px each). The window's size reaches the UI as `{"event": {"Viewport": {"width": w, "height": h}}}` (logical pixels; the windowed player sends it; headless, the first root's canvas). A pointer over a control, a box with a background or a `"pointer": "Stop"` node is consumed: click-to-move ignores it (`ConsumedActions`); `"pointer": "Ignore"` passes it through.
- **Text entry (2.7b.3):** `UiTextBox {text, placeholder, multiline, max_len?, password, editable, caret, anchor, wrap}` (`caret` and `anchor` are byte offsets on character boundaries; `password` masks drawing only), `UiSpinBox {value, min, max, step, decimals}` (with a `UiTextBox` on the same entity, which shows the value; typed numbers commit on Enter or when focus leaves) and `UiList {selected, multi}` (its children are items; Ctrl adds, Shift selects a range; `ui_ctrl` and `ui_shift` in the starter map). Typing is input: `{"event": {"Text": {"Insert": "hello"}}}` or `{"event": {"Text": {"Edit": {"key": "Backspace", "select": false}}}}` (`Left`, `Right`, `Up`, `Down`, `Home`, `End`, `Backspace`, `Delete`, `SelectAll`, `Copy`, `Cut`, `Paste`, `Enter`; `select` extends the selection). It goes to the focused text box, replays record it, and while a text box has focus every key-bound action is consumed. Signals: `UiTextChanged {text}`, `UiTextSubmitted {text}`. Copies and cuts write the engine's clipboard (`ui.clipboard`); the windowed player mirrors it to the OS clipboard and turns an OS paste into typed text.
- **World-space UI (2.7b.3):** a `UiRoot` with `"space": {"World": {"offset": [x, y, z], "pixel_size": s}}` on an entity with a `Transform` is drawn centered at the entity's world position (parents count) plus `offset`, through the drawing camera, `s` screen pixels per UI pixel, over the 3D scene (U11). It is hidden behind the camera or off screen; world roots draw far to near, under screen roots. They draw in `capture.screenshot` and the window; in projects with `[render]`, interaction, `ui.inspect` and `ui.hit_test` also see them through the highest-priority camera (M3 3.0c), so world buttons take clicks. Their node boxes are in the root's UI space; the root's `map` places it on screen. Damage numbers tween `UiRoot` `/space/World/offset/1` and `UiStyle` `/opacity`.
- The UI's layout and drawing are presentation and never change a world hash; controls' values and `UiState` are simulation state. Animate numeric fields with `Tweens` (e.g. `UiStyle` `/opacity`, `UiProgress` `/value`).
- **Check it:** `ui.inspect {"width": 1280, "height": 720}` (or `{"world": "play"}`, or `{"entity": id}` for one subtree) reports every node's `rect`, `content`, `clip`, `opacity`, resolved `style`, text `lines` and `state`, plus `problems` (components that failed their checks and drew with defaults). `ui.hit_test {"x": 640.0, "y": 360.0, "world": "play"}` names the node and widget under a point, the `part` (`Body`, `{"Row": i}`, `{"Tab": i}`, `{"Thumb": "Vertical"}`, …), the `path` from the root and the `cursor`; click it with `input.inject` (`PointerMove`, then a left `MouseButton` press and release). `capture.screenshot` draws the UI unless `"ui": false`; `"ui_scale": 2.0` draws it at high density; `{"debug": ["ui_bounds"]}` outlines every node.
- In the Studio, the UI/UX designer (`concordia-ui`) builds and themes screens and checks them with `ui.inspect`, `ui.hit_test`, injected clicks and screenshots; QA clicks through menus the same way.

## Rules
- Every mutating call needs an actor: `"actor": "agent:<role>"` or the session default. Grammar: `<human|agent|system|tool|script>:<name>[#n]`, lowercase names.
- Entity ids are UUID strings. If you pass a name instead, the error tells you the matching id.
- Component values are JSON in serde's shape: structs are objects, glam vectors are arrays (`Vec3` = `[x, y, z]`, `Quat` = `[x, y, z, w]`), enums are `"Variant"` or `{"Variant": payload}`.
- While your transaction is open, other sessions' edits fail with `TxnConflict`. Open transactions abort after 120 s or when the session closes.
- The simulation never changes the edit world (ADR-0032).

`events.subscribe` makes the WebSocket connection receive JSON-RPC notifications, `{"method": "events.event", "params": {"topic", ...}}`:
- `edit`: one per committed transaction, undo or redo, with `method`, `txn`, `label`, `actor`, `entities` and `undo`;
- `scene`: `event` is `opened`, `new` or `saved`, plus the `path`;
- `sim`: `method`, `tick` and `state`;
- `pending`: one per call that changes the world inside an open transaction (`pending: true`, with `method`, `txn`, `label`, `actor` and that call's `entities`), and one when a transaction is aborted (`aborted: true` and its `entities`). Use it to show work in progress, such as a gizmo drag, before the commit;
- `log`: `latest` (the newest log record's seq) after a call wrote log records; fetch them with `log.tail`;
- `asset`: one per file `material.set` writes or `asset.import` imports, with its `path`, `id` and `actor` (the editor redraws and refreshes the Inspector);
- `studio` (projects with `[studio]`): one per new Studio journal entry (task changes, reviews, file edits, and `question_asked`, `question_answered` and `question_escalated`), with its `seq`, `ts_ms`, `actor`, `kind` and the kind's fields.

Edits made by other clients arrive too, which is how the editor sees agents work. Over stdio or MCP, poll `log.tail` instead. If a client falls more than 1,024 events behind, newer events are dropped, so re-read state with `query.run`.

`capture.screenshot` renders offscreen at the requested size (default 768×432) from the highest-priority `Camera`, unless `camera` names one. MCP clients receive `image` as PNG image content and the other fields as text. Pass `world: "play"` after `sim.step` to see the simulation. To be visible, a scene needs a `Transform` + `Camera` entity, `MeshRenderer` entities (e.g. `{"mesh": "builtin:mesh/cube", "material": "builtin:material/default"}`) and usually a `DirectionalLight`.

`query.run` `where` entries are `{"path": "Transform/translation/0", "op": "gt", "value": 4}` with `op` one of `eq ne lt le gt ge contains`. Rows are sorted by id; pass `next_cursor` back as `cursor` for the next page (default limit 100).

## Errors
Errors are JSON-RPC errors whose `data` says what to do next (ADR-0031): `kind`, `suggestions` (best first), and where useful `pointer`, `expected` (the schema at the pointer), `example`, `see` (a `concordia://` resource), plus kind-specific fields such as `holder` for `TxnConflict`.

| Code | Kind | Typical fix |
|---|---|---|
| −32001 | `EntityNotFound` | find ids with `query.run {"with": ["Name"]}` |
| −32002 | `ComponentNotRegistered` | use a suggested name; list names with `schema.get {}` |
| −32003 | `ValueInvalid` | fix the value at `pointer` to match `expected` |
| −32004 | `ActorRequired` / `ActorMalformed` | pass `"actor": "agent:<role>"` |
| −32005 | `TxnConflict` | wait for `holder` to commit or abort, then retry |
| −32006 | `NothingToUndo` / `NothingToRedo` | check `txn.history` |
| −32007 | `SceneIo` | check the path and permissions |
| −32008 | `SceneParse` | fix the file at `line`/`col`, or run `concordia fmt` |
| −32009 | `NoSceneOpen` | `scene.new` or `scene.open` |
| −32010 | `SceneDirty` | `scene.save`, or pass `"discard": true` |
| −32011 | `NotPlaying` | `sim.step` or `sim.play` first |
| −32012 | `TxnNotFound` | use the id from `txn.begin`; it may have timed out |
| −32013 | `GpuUnavailable` | run `concordia gpu-probe`; rendering needs Metal (macOS) in M1 |
| −32014 | `TaskNotFound` | list tasks with `task_list` |
| −32015 | `TaskTransition` | follow todo → in_progress (`task_claim`) → in_review → done (`task_approve`) |
| −32016 | `NotPermitted` | a Studio gate or your role's scope refuses this; see `studio_roster` |
| −32017 | `EngineExited` | the shared engine's host (editor or another server) exited; call again to reconnect, then `scene_open` your scene (unsaved edits are gone) |
| −32018 | `ScriptFailed` | fix the module the message names, rebuild it, then `script.reload` |
| −32019 | `ReplayMismatch` | open the scene and build the replay was recorded with (see `mismatches`), or pass `"force": true` |
| −32602 | `InvalidParams` | match `expected` at `pointer` |

## Journal
Every commit, undo, redo, abort and save is appended to `.concordia/journal/<scene-id>.cmdlog.jsonl` with its actor (format: `crates/concordia-command/AGENTS.md`).

## Transports
- stdio: one JSON-RPC message per line, one session per process.
- MCP with Agent Studio (`[studio]`): every engine call made from Claude Code is stamped by the Studio hook with your role. Each agent instance gets its own session and actor (`agent:<role>#n`). Calls outside your role's tools or paths fail with `NotPermitted`, and so do edits when the hooks aren't running. Don't pass `actor`; it is ignored.
- WebSocket: `ws://127.0.0.1:<port>/?token=<token>`, localhost only; the URL and token are in `.concordia/headless.json` (mode 0600). Browser origins other than localhost are rejected.
- One engine per project (ADR-0082): `concordia mcp`, the editor and `concordia headless --ws` attach to the live engine named in `.concordia/headless.json`, or host one and publish that file. Your edits show live in the editor, and the editor's in yours. If the host exits, the next call fails with `EngineExited`; the call after it reconnects.
